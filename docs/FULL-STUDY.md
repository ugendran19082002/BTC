out-of-the-money premium on the daily contract, sizes from two years of settled
chains, and places and manages live orders. It began on **4 September 2026** as

the following three weeks.

## 3. Backend (`app/server/`)

Fastify 5 on Node 24, native TypeScript via `tsx`. Four dependencies:
`fastify`, `@fastify/cors`, `pg`, `qrcode`. No ORM, no framework on top of the
framework.

### Layering

```
http/routes/*.ts   8 files, 68 routes      ← the only place HTTP exists
      │
trading/service.ts                         ← paper/live switch, server-authoritative
      │
trading/engine.ts  (1,946 lines)           ← no clock, no timers, no I/O of its own
      │ ExchangePort (~10 methods)
      ├── trading/exchange/delta.ts        ← THE ONLY FILE THAT MOVES MONEY
      └── trading/exchange/paper.ts        ← the simulator
      │
trading/store.ts ──► PostgreSQL: trades, trade_events

domain/*.ts        pure maths, no I/O      ← score, ev, probability, patterns,
                                             indicators, market-state, bs,
                                             calibration, forecast, break-risk
market/*.ts        Delta public API        ← chain, flow, moves, sockets, snapshots
```

The separation holds under inspection. `domain/` has no imports outside itself
and the type modules; `engine.ts` starts no timer — time arrives as `now()` and
work as `poll()`, which is why 81 engine cases including races, disconnects and
restart recovery run deterministically in under a second.

### The seven rules, and what each one cost

`docs/ARCHITECTURE.md` states them; this study confirms each is enforced in
code and each traces to a dated incident in `TODO.md`:

1. **Read state from the exchange, never from local belief.** Broken three
   times. `protect()` is now a reconciler that reads the book, classifies each
   leg, prefers an in-place `PUT`, and only ever cancels *verified*.
2. **A simulator is evidence about our logic, never about the venue's.** On
   9 Sep a take-profit trigger fired the instant it landed — twice — and **five
   tests asserted it fired correctly**, because `PaperExchange` had been written
   from the same misreading of the docs as the engine.
3. **Position is counted from fills.** `position = exit.size - entry.size`,
   written that way round so a closed trade is `0` and never `-0`.
4. **The engine owns no clock.**
5. **The log is only worth reading if everything in it needs fixing.**
   `http/refuse.ts` marks deliberate 4xx; `worthLogging(status, deliberate)` is
   the whole rule. This works — see §5.
6. **A target is a price; a stop is an exit.** Target = resting reduce-only
   limit buy. Stop = trigger on the mark.
7. **A feed's age is the newest of all its sources.** On 21 Sep a dead ticker
   socket reconnected 3,833 times and was never heard, because silence was
   measured from the dead socket's last message.

Rule 6 has a **sequel worth noting**: on 24 Sep a stop asked for at 70 filled
at 79, because the stop went out as a limit priced 50% through its own trigger
— a market order wearing a hat. `STOP_LIMIT_SLACK` is now 15%, `slippageOf()`
measures every exit against what was asked, and a fill missing its trigger by
≥5% raises an alarm.

### Concurrency

One per-trade promise-chain mutex in `engine.ts`. Public methods take the
queue, `*Inner` methods assume they are already inside one. Mixing those up is
how a poll loop once raced a screen action into six duplicate take-profits.

### HTTP surface

68 routes across 8 files. Auth is one session cookie; `PUBLIC_ROUTES` contains
exactly one entry, `/api/health` (see §7.2). CSRF is defended beyond
`SameSite=Strict` by requiring an `Origin`/`Referer` naming this host on every
`POST`/`PUT`/`PATCH`/`DELETE` — necessary, because anything under
`thannigo.in` is same-site and gets the cookie. `trustProxy` is a fixed list of
private ranges, not `true`, because `true` let a sign-in limiter be walked past
by writing a new `X-Forwarded-For` each attempt.

### Analytics service

`analytics/` is a Python FastAPI service, display-only, **internal by
construction**: no host port, no credentials, no path to an order, and
`docs_url`/`redoc_url`/`openapi_url` all `None` so nothing about it is
advertised. The Node API calls it and shows its own figures when it cannot
reach it. 41 tests pass, 5 skip.

### What's strong

- **One formatter.** `lib/format.ts` is the only place a number is written.
  Rupees main, dollars small, at ₹85. This matters because
  `money = quoted × contracts × 0.001` — a quote of 19 on ten contracts is
  **$0.19, not $19** — and getting that wrong by 1000× reached the screen once.
- **The server is the authority.** The paper/live switch is server-decided and
  refuses to flip with a position open. A page that can put itself into live
  mode by setting its own state flag will eventually do it by accident.
- **Failures are reported.** Browser errors `POST /api/errors` into the same
  log the server writes to.
- **954 tests pass, and the typecheck is clean.** `PositionsCard.test.tsx`
  alone is 832 lines.

- `styles.css` is **3,510 lines** and the single most-churned file in the repo.
  Tailwind is present, so this is the overflow that Tailwind did not absorb.
- `lib/overview.ts` is **1,315 lines** of desk computation in one module —
  the largest non-generated TypeScript file outside `engine.ts`. It has a
  1,000-line test file beside it, which is the mitigation, not the fix.
- `App.tsx` at 822 lines holds routing, layout and top-level state together.

None of these is a defect. All three are the places a fourth week of work will

### The migration ledger

31 migrations, defined in **TypeScript** (`db/migrate.ts`), not SQL files.
Every property you want is there and each one is justified in the file's own
docstring:

- permanent ids, convention `<schema>-NNN-what-it-does`; renaming one re-runs it
- each inside a transaction; **a failure rolls back and stops the boot**,
  because starting a trading engine against a half-migrated database is worse
  than not starting
- `pg_advisory_lock` around the whole list, so a deploy restarting the API
  while the old one is still up does not race
- one ledger across every schema, and `/api/health` returns the full applied
  list

This is better than most production systems manage.

### Event sourcing

`trade_events` is append-only, keyed `(trade_id, seq)` unique, with
`ON DELETE CASCADE` from `trades`. `hydrate()` replays events through
`recompute()`, so **a fix to the arithmetic repairs closed trades too**.
687 events:

| Kind | Count |
|---|---:|
| `fill` | 200 |
| `protection_placed` | 148 |
| `entry_submitted` | 80 |
| `protection_failed` | **74** |
| `sibling_cancelled` | 43 |
| `add_done` / `add_submitted` | 40 / 40 |
| `exit_submitted` | 31 |
| `precheck_failed` | 12 |
| `reconciled` / `entry_cancelled` | 7 / 7 |
| `entry_timeout` / `entry_rejected` | 3 / 2 |

**`protection_failed` at 74 against 148 `protection_placed` looks alarming and
is not.** Broken down: 68 are `no_position_for_reduce_only`, all on
**8 September** — the loop that sent reduce-only before Delta had registered
the fill, which is exactly what rule 1 was written to stop. The remaining 6 are
`unsupported`, last seen **12 September**. Neither has recurred in fourteen
days. This is a fixed bug still visible in its own audit trail, which is what
an append-only journal is for.

The 12 `precheck_failed` rows are the desk refusing on purpose — spread over
limit, premium below the 5.00 floor, already holding the contract — and each
carries a sentence a person can read.

### The empty error log is a result, not a gap

`errors` has **0 rows** on a live system with 94 trades. That is rule 5
working: `http/refuse.ts` keeps deliberate refusals out, and `test/env.ts`
gives every test process its own `btc_test_<random>` database so the suite can
no longer file fixture refusals into the desk's real log. It used to — two rows
with 72 folded occurrences between them turned out to be a `client_order_id`
fixture and a stack ending in `node:assert`.

## 7. Findings

### 7.1 🔴 A generated file is imported by `HEAD` but not committed to it

**Severity: blocks a deploy from a clean checkout.** Commit `098dcda` ("feat:
add break risk domain logic, API endpoint, and momentum study data") added
seven files. One of them, `app/server/src/market/break-risk-now.ts`, opens:

```ts
import { BREAK_CARRY, REACH_STEPS_ATR } from '../domain/break-carry.data.js';
```

`app/server/src/domain/break-carry.data.ts` is **not in `HEAD`**:

```
$ git cat-file -e HEAD:app/server/src/domain/break-carry.data.ts
fatal: Not a valid object name HEAD:app/server/src/domain/break-carry.data.ts

$ git worktree add --detach /tmp/clean HEAD && ls /tmp/clean/…/src/domain/ | grep break
break-risk.ts                      # break-carry.data.ts absent
```

`app/server/src/http/routes/desk.routes.ts:35` imports `breakRiskNow` from that
module, so the failure is not confined to a leaf — the whole route tree fails
to construct. Measured on the tree as it stood at the start of this study, with
the file absent:

```
$ npm run typecheck                       # app/server
src/market/break-risk-now.ts(3,46): error TS2307:
  Cannot find module '../domain/break-carry.data.js'

$ npm test                                # app/server, against the harness DB
Error [ERR_MODULE_NOT_FOUND]: … /src/domain/break-carry.data.js
  imported from .../src/market/break-risk-now.ts
→ 1,069 assertions pass; six suites cannot load:
  e2e/strategy-lifecycle, http/auth-flow, http/auth-gate,
  http/chain-route, http/strategy-clone, http/stream
```

Every one of those six builds the app. This is the same systemic shape
`FULL_AUDIT.md` recorded on the sibling project: one missing module takes down
unrelated routers and nothing in the failure names the cause.

**Current state.** The file was regenerated at 23:49 during this study by a run
of `src/backtest/momentum-study.ts`, and is now staged. Its own header says
what it is:

```ts
// GENERATED by src/backtest/momentum-study.ts -- do not edit; rerun the study instead.
```

With it present, the same commands give **1,127 assertions passing, 0 failures,
exit 0**, and a clean typecheck. So the immediate fix is simply to commit it
along with the regenerated `research/MOMENTUM-MEASURED.txt`.

**The durable fix matters more.** This file is generated, is not produced by
any build step, and is not in `.gitignore` — it is checked-in generated output
that nothing enforces. That is exactly how it went missing: a commit that added
the consumer and forgot the artefact. Either commit it and add a test that
asserts it is in sync with the study (the pattern `ARCHITECTURE.md` §8 already
uses for four other generated documents on the sibling project), or make
`momentum-study.ts` a build step so it cannot be absent. Leaving it as an
unenforced checked-in artefact means the next regeneration can silently diverge
from the numbers in `MOMENTUM-MEASURED.txt` that justify it.

The untracked-then-staged `app/web/src/lib/break-risk.ts` shows the feature is
still mid-flight; the web half had not been committed at all.

unauthenticated response to `{"ok":true}` and keep the detail behind the
session.

The headline reads well and is misleading, and the file says so itself:

> 5m, 9,981 signals: target first in **80.0%** of the ones that finished …
> *of which the target was ALREADY passed at the call: 2,701 calls (27.1%)*

After fees (0.05% taker each side), **every policy at every timeframe is net
negative**:

| Timeframe | live plan (level ± 1 ATR) | best policy tested |
|---|---|---|
| 5m | −0.611 R | −0.612 R |
| 15m | −0.321 R | −0.284 R |
| 30m | −0.210 R | −0.149 R |
| 1h | −0.106 R | −0.116 R |

And the filter search does not rescue it: at 5m and 15m, **0 of 582 filters**
were positive after fees in both 2024 and 2025. At 30m two were, at 1h one was
— and all three then lost money in 2026 out of sample. The file marks each
`fails`.

This is good research and an honest report. The finding is that **a 71–80% hit
rate is not an edge when a quarter of the "hits" were already past their target
when the call was made, and the survivors do not clear fees.** The same lesson
the sibling project learned from a 98% win rate that lost money.

The risk is presentational, not analytical: `SignalStrip`, `MarketState` and
`DecisionCards` surface these calls on the Live screen, and nothing on that
screen carries the measured result. A hit rate shown without its net-R is the
number that gets acted on. Either show the replayed net R beside the call, or
mark the strip as informational.
